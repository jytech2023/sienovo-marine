## 2. 测试概述

### 2.1 产品简介

Sienovo Marine 遥控 App 是面向淡水水域无人船作业的移动端远程控制软件，运行于 iOS 与 Android 系统，主要应用于钓鱼打窝、海渔作业等场景。App 通过 4G 网络与无人船设备建立连接，单条链路同步承载控制指令、遥测数据与摄像头画面。

### 2.2 测试范围

本次测试覆盖 App v1 已发布功能：

- App 安装、启动与权限申请
- 用户登录 / 鉴权
- 船舶列表、绑定与解绑
- 船舶连接与断开
- 实时遥测显示（GPS、电量、信号、深度、水温）
- 电机 / 舵向控制（油门、方向）
- 手动投饵控制
- 摄像头实时画面与红外、补光控制
- 组件健康状态与故障告警
- 4G 链路保持

不在本次测试范围内：

- 服务器端管理后台 / Web 控制中心
- 真实硬件无人船的机械结构与电气性能
- Phase 2 的 300m 本地射频与 BLE 控制

### 2.3 系统组成（用户视角）

| 组成部分     | 说明                                   |
| ------------ | -------------------------------------- |
| 遥控 App     | 安装于客户手机（iOS / Android）        |
| 无人船设备   | 出厂时已绑定客户账号，通过 4G 接入云端 |
| 云端服务     | 由 Sienovo 部署运维，对客户透明        |

### 3.1 测试设备

App v1 仅在 Sienovo 出厂指定的客户机型上验收，不做跨品牌 / 跨机型兼容性测试。具体机型与系统版本由 Sienovo 在交付时与客户确认并填入下表。

| --------- | ---------------------- | ---------- |
| iOS       | _（交付时填入）_       | _（同左）_ |
| Android   | _（交付时填入）_       | _（同左）_ |

### 3.2 网络环境

App 仅支持通过 4G 移动网络与无人船设备建链。Wi-Fi、5G、弱网与信号干扰相关测试不在 v1 范围内。

| 场景    | 要求                                       |
| ------- | ------------------------------------------ |
| 4G      | SIM 卡数据可用，运营商信号 ≥ 2 格          |

### 3.3 无人船与配件

- 至少 1 艘已激活并绑定测试账号的无人船设备。
- 备用电池 ≥ 2 块、饵料若干。
- 测试水域：开阔水面，水深 ≥ 0.5m，避开航道与人群。

### 3.4 测试前准备

1. 在 App Store / 应用市场或客户提供的安装包获取最新版本 App。
2. 开放测试账号并完成登录。
3. 确认手机定位、相机、本地网络等权限授予 App。
4. 出航前在岸边检查船体、电量、饵料、螺旋桨与饵舱。

## 4. 验收方式

- **验收方法**：客户人员按本文档逐项实操，结合现场作业场景验证。
- **执行节奏**：安装与登录冒烟 → 主功能用例 → 异常处理 → 整体回归。
- **优先级说明**：
  - **P0** — 核心功能，必须 100% 通过。
  - **P1** — 主要功能，通过率 ≥ 95%。
  - **P2** — 次要功能 / 体验项，通过率 ≥ 85%。

### 4.1 用例编号规则

`TC-<模块代号>-<序号>`，例如 `TC-CTRL-001` 表示控制模块第 1 个用例。

| 模块代号 | 模块名称               |
| -------- | ---------------------- |
| APP      | 安装、启动与权限       |
| AUTH     | 登录与账号             |
| BOAT     | 船舶列表与绑定         |
| CONN     | 船舶连接与链路         |
| TELE     | 实时遥测显示           |
| CTRL     | 控制（电机 / 舵）      |
| BAIT     | 投饵控制               |
| CAM      | 摄像头控制             |
| HEALTH   | 组件健康与故障告警     |

## 7. 通过 / 不通过判定标准

### 7.1 通过标准

- 所有 **P0** 用例 100% 通过。
- **P1** 用例通过率 ≥ 95%。
- **P2** 用例通过率 ≥ 85%。
- 已发现的缺陷均有书面记录、责任人与修复计划。
- 无 **致命级 / 严重级** 未关闭缺陷。

### 7.2 不通过条件

满足任一即视为不通过：

- 任一 P0 用例失败且未修复。
- 存在导致 App 崩溃、长时间无响应或失控的缺陷。

## 8. 缺陷管理流程

1. **发现**：测试人员在执行用例时记录复现步骤、截图 / 录屏、设备日志。
2. **登记**：填写缺陷单（编号、模块、严重等级、复现步骤、期望与实际结果、机型与系统版本）。
3. **分级**：按严重程度分为 致命 / 严重 / 一般 / 轻微。
4. **修复与回归**：开发修复后转测试回归，回归通过方可关闭。
5. **复盘**：阶段性测试结束后形成《测试报告》，对未关闭缺陷形成处理意见。
