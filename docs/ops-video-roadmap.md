# Sienovo Marine · 运维：实时视频路线决策

**仅运维内部参考**——不公开给硬件组（他们只需知道"未来要切，先准备好硬件 H.264 编码模组"）。

## 现状

- v1 走 **MQTT 缩略图**（1-2 Hz JPEG ≤ 30KB）通过 AWS IoT Core 在 [§5.3](./hardware-integration.md) 协议下传送
- 预计 2-3 个月内不需要真实视频，靠缩略图 + 遥测指挥已经够用
- 但**摄像头模组选型现在就要定**——硬件团队的物料长 lead time

## 为什么 v1.5 要换掉 MQTT 摄像头

| 维度 | MQTT 摄像头（当前） | 真实需求 |
|---|---|---|
| 单帧上限 | 128 KB | 720p I-frame 经常 > 100KB |
| 延迟 | 150-300ms | 远程驾驶感差 |
| 计费 | 按消息计费，30fps × 100 船 = 月费爆 | 不可接受 |
| 协议 | TCP / TLS | 视频走 UDP/SRTP 才稳 |

## 候选方案对比（v1.5 实时视频）

| 维度 | AWS KVS WebRTC | 腾讯云 TRTC | 阿里云 RTC | 声网 Agora |
|---|---|---|---|---|
| **接入点** | ap-east-1 香港 | 广州 / HK 等 | 上海 / HK | 全球 SD-RTN |
| **深圳延迟** | 40-80ms | **30-50ms** | 50-80ms | 30-60ms |
| **国内稳定性** | 跨境，偶发卡顿 | **专网，稳定** | 专网，稳定 | 多边缘节点 |
| **价格 / 1000 分钟** | ~$1（~¥7） | ~¥6-10 | ~¥5-12 | ~¥7（$0.99） |
| **免费额度** | 信令 channel 50 万次/月 | **10000 分钟/月** | 10000 分钟/月 | 10000 分钟/月 |
| **ESP32 / IoT SDK** | KVS WebRTC C SDK（重） | **TRTC-Lite for IoT**（专做嵌入式） | 无原生 ESP32 | Agora IoT SDK |
| **浏览器 SDK 成熟度** | 中 | **高** | 中 | 高 |
| **与 IoT Hub 同账号联动** | ✅（同 AWS） | ✅（如果 IoT 也迁腾讯） | ✅（如果 IoT 也迁阿里） | ❌（独立产品） |
| **海外可用** | ✅ | 弱 | 中 | **强** |

## 推荐路线

### 单船单看（v1.5 起步）

**腾讯云 TRTC** —— 免费额度（10000 分钟/月）覆盖 1 船 × 1 看 × 30 min/天 用法，不花钱；TRTC-Lite for IoT 是市面唯一为 ESP32 适配的 RTC SDK，船端嵌入门槛最低。

### 多船多看（v2 量产期）

| 客户区域 | 选择 |
|---|---|
| 国内为主 | **TRTC** + 腾讯云 IoT Hub（v2 整体迁腾讯） |
| 出海混合 | **TRTC（国内） + Agora（海外）** 双栈，按客户路由 |

## 为什么不是 AWS KVS WebRTC

虽然能保持单一云栈，但：
- 跨境延迟 40-80ms vs 国内 30-50ms，远程驾驶体感差异明显
- ESP32 SDK 是给 Linux 嵌入式的，移植到 ESP32 工作量大
- 国内客户在 push 节点上吃不到 SD-RTN 边缘加速
- 同等流量下贵约 30-50%

## 与 IoT 后端选择的关系

| IoT 平台 | 推荐 RTC |
|---|---|
| AWS IoT Core（**当前**） | TRTC（混栈，按客户决定迁不迁 IoT） |
| 腾讯云 IoT Hub（如果未来迁） | TRTC（同账号，最优） |
| 阿里云 IoT Platform（如果未来迁） | 阿里云 RTC（同账号），或 TRTC 跨家 |

**当前架构是 AWS IoT + 腾讯 TRTC 混栈最实用**——MQTT 控制信令走 AWS（成本 KB 级可忽略），视频走 TRTC（成本 GB 级走国内便宜）。

## 迁移触发条件

下面任一条件触发时启动 v1.5 实时视频接入：

- [ ] 客户明确要求"打开摄像头看现场"
- [ ] 单船摄像头帧 SVG 缩略图已经满足不了演示需要
- [ ] 月有效船 ≥ 5 艘（消息成本上来时 push factor 出现）
- [ ] 出现"远程协同钓鱼直播"等多人围观需求

## 迁移工作量预估

| 项 | 工作量 |
|---|---|
| 腾讯云账号开通 + IM SDK App ID 申请 | 0.5 天 |

| 文档（hardware-integration.md §5.4 出 v1.5 协议） | 0.5 天 |
| **合计** | **~7-10 天** |

## 当前对硬件团队的硬约束

只告诉硬件组：
1. 摄像头模组选**硬件 H.264 编码款**（不要 JPEG-only）
2. 4G 模组预留 ≥ 1 Mbps 上行余量
3. 内存 / Flash 预留给未来 TRTC-Lite SDK（参考占用 ~150KB ROM + 200KB RAM）

具体跑哪家方案、SDK 怎么集成，到 v1.5 立项时再发协议文档。**不要让硬件组现在就跨家研究 SDK**——浪费精力。
